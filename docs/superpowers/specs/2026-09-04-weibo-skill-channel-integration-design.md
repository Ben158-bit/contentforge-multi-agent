# 微博电商推理 Skill 渠道接入设计

## 目标

用户在前端选择目标渠道“微博”后，现有流水线自动使用微博电商推理规则生成和审校文案，不增加额外交互步骤。

## 现状与边界

- backend/app/templates/channels.yaml 已注册 weibo 渠道。
- 文案创作和审校消息已将渠道的 copywriting_guide 注入模型消息。
- 因此本次不新增 skill loader、不修改图编排、不改变 API 和前端渠道选择。
- 微博规则只影响 channel_id == weibo；其他渠道行为保持不变。

## 设计

将 weibo.copywriting_guide 扩展为四组规则：

1. 推理结构：现象 → 机制 → 动作 → 指标/结果；没有数据时标注假设，不伪造结果。
2. 表达模式：结论前置、场景化痛点、数字锚点、对比、低门槛互动、适度反常识；均使用抽象句式，不仿写具体博主。
3. 微博成文约束：280 字内；一句钩子、1-2 个核心信息点、互动或 CTA、2-4 个话题标签；信息密度高、少企业腔。
4. 研究与合规边界：多样本归纳优先；观点与事实分开；不编造销量、价格、效果和微博来源；避免夸大承诺、虚假稀缺和整段复制。

这些规则会被现有的文案创作 Agent 和审校 Agent 同时读取。策略 Agent 继续接收 channel_id，但不额外加载文件。

## 测试设计

在现有后端测试中增加：

- weibo 渠道配置包含多样本推理和 280 字约束。
- build_copywriting_messages 生成的 user 消息包含推理结构、证据边界和微博输出约束。
- 非微博渠道不包含微博专属规则。

测试只验证 Prompt 合同，不调用真实模型。

## 失败处理

如果渠道模板缺少指南，现有逻辑继续使用“无额外指南”；不会阻塞任务。YAML 语法错误由已有模板加载测试捕获。

## 验收标准

- 前端选择微博并创建任务时，API 行为不变。
- 文案 Agent 和审校 Agent 都能看到新增微博规则。
- 现有测试全部通过，新增测试证明微博规则隔离于其他渠道。
